# Design Arena Agents Overview

## Project Snapshot
- **App name:** `spaced-app`
- **Generated by:** DesignArena AI Agent
- **Stack:** Next.js 14 App Router, React 18, TypeScript, Tailwind CSS, Vitest, Testing Library.
- **Entry point:** `src/app/page.tsx` renders the entire experience; no nested routes yet.
- **State/persistence:** Client-only React state with `useState`, `useMemo`, `useCallback`; session saved to `window.localStorage` under `agentic-spaced-repetition-v1`.

## Domain Model
- **StudyCard:** (`src/lib/spacedRepetition.ts`) encapsulates prompt, answer, optional image, scheduling metadata (`dueAt`, `intervalDays`, `easeFactor`, `repetitions`, `lastReview`).
- **ReviewGrade:** Enum union (`again | hard | good | easy`) drives the SM-2-inspired scheduling.
- **Sample deck:** (`src/lib/sampleData.ts`) builds a seeded set of cards with staged review offsets and ease factors for demo purposes.

## Core Behaviors
1. **Deck bootstrapping:** On first load, `buildSampleDeck()` seeds six cards; subsequent loads hydrate from localStorage (with graceful fallback on JSON parse errors).
2. **Review loop:** `getDueCards` selects cards with `dueAt <= now`; grading invokes `scheduleCard` to recalculate intervals, ease, repetitions, and `dueAt`.
3. **Session telemetry:** `sessionStats` tracks counts of grades since last reset; UI surfaces totals alongside upcoming reviews.
4. **Card authoring:** Users submit prompt/answer plus optional URL or uploaded image (converted to base64 for preview/persistence, limited to 4 MB).
5. **Utilities:** `nextDueIn` formats relative due times; `formatReviewDate` surfaces the prior review timestamp in local time.

## UI Layout Notes
- **Visual language:** Dark, card-based dashboard with rounded containers, translucent backgrounds, and accent colors for grade buttons.
- **Main sections:**
  - Header summary cards (Cards, Due Now, Session Reviews, Next Due).
  - Review queue with reveal/grade workflow and current card details.
  - Form for adding cards, including live image preview and error feedback.
  - Card library list with metadata badges and delete actions.
- **Design system:** Tailwind utility classes only; global fonts from `next/font` Geist Sans/Mono, but global body font still defaults to system (`globals.css`), creating a mild mismatch.
- **Accessibility:** Buttons use descriptive labels; however, there are no ARIA enhancements, keyboard shortcuts, or focus states beyond Tailwind defaults.

## Operational Considerations
- **Persistence scope:** All data stored client-side; no backend or API routes.
- **Imaging:** `next/image` used with `unoptimized` flag to bypass remote domain allowlists; preview uses uploaded base64 string when present.
- **Metadata:** `src/app/layout.tsx` still contains default Next.js `metadata` (title/description) that should be branded for the product.
- **Testing:** Vitest configured but no test files; algorithm correctness currently unverified by automated tests.

## Observed Gaps / Opportunities
- Missing deck import/export, spaced repetition analytics, and spaced intervals history for users.
- Lack of responsive layout tweaks for very narrow screens (complex grids collapse but may overflow).
- No error boundary or validation feedback around prompt/answer whitespace-only submissions (beyond disabled state).
- Schedules reset loses per-card `lastReview` history without log.

Use this document as the quick reference for how the current agentic spaced-repetition experience is organized and where core behaviors live.
